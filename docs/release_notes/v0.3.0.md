# v0.3.0 — Research workflow & core–satellite strategy

**Release date:** 2025-03-17

This release turns aShare into a full research loop: single backtest, multi-symbol parameter sweeps, YAML-driven experiments, and walk-forward optimization, plus the first strategy built for that loop — the core–satellite mean reversion strategy.

---

## Highlights

- **YAML experiment specs** — Define experiments in a file (`experiment_name`, `strategy`, `symbols`, `date_range`, `parameters`, `grid_search`, `execution`); run with `ashare experiment path/to/spec.yaml`.
- **Grid search engine** — Cartesian product over parameter dimensions; supports scalars and list-valued params (e.g. Z-score bands).
- **Core–satellite mean reversion** — New strategy with core/satellite sizing, Z-score entry/exit, trend filter, and extensible entry mode.
- **Walk-forward optimization** — `ashare walk-forward` for train/test rolling windows and out-of-sample validation.
- **Experiment runner** — Multi-symbol, multi-parameter runs with CSV results and per-run artifacts when using a spec.

---

## Features

| Feature | Description |
|--------|-------------|
| **Experiment spec (YAML)** | Declarative specs with validation; optional execution overrides (`initial_cash`, `commission`). |
| **Grid search** | `generate_parameter_sets()` for base parameters + grid dimensions; used by both spec-driven and ad-hoc experiment flows. |
| **Core–satellite strategy** | `core_satellite` in strategy registry; configurable core/satellite size, trade unit, Z-entry/Z-exit, trend filter. |
| **Walk-forward** | Rolling train/test windows; in-sample best params, out-of-sample metrics, and results CSV. |
| **Experiment command** | `ashare experiment` accepts either a YAML spec path or `--strategy`, `--symbols`, `--param`, `--start`, `--end`. |

---

## Improvements

- **Research efficiency** — One CLI for backtest, parameter sweep, and walk-forward; outputs under `outputs/` and `experiments/` with consistent metrics.
- **Reproducibility** — Spec files and per-run `config_snapshot.yaml` + `metrics.json` support reproducible and auditable runs.
- **Docs** — System architecture, PRD, design docs, and user manual for core–satellite strategy aligned with current behaviour.

---

## Developer notes

- **Strategy API** — New strategies register in `ashare.strategies.STRATEGY_REGISTRY` and can be parameterized via `strategy_params` in `run_backtest()` and experiment flows.
- **Experiment spec schema** — Required: `experiment_name`, `strategy`, `symbols`, `date_range` (with `start`/`end`). Optional: `parameters`, `grid_search`, `execution`. See `configs/experiments/core_satellite_demo.yaml`.
- **Tests** — Coverage for experiment spec loading, grid expansion, experiment runner, walk-forward windows, and core–satellite / mid_freq_ma strategies.

## Upgrade

- Bump to `ashare>=0.3.0`; no breaking CLI changes. Experiment spec is additive; existing `ashare backtest` and ad-hoc `ashare experiment` usage unchanged.
